## DOP-014 — One consistent content grid (kill the inconsistent right-gutter) — Ross: "do whatever you think is best"
**The problem:** pages disagree on content width — some cap content and leave a ~270px wasted right gutter, others run full-width, so the app feels inconsistent page-to-page.

**The call:** pick ONE content-container convention and apply it uniformly across the main app pages (dashboard, projects, library, collection, recipes, tools, focus, planner). Recommended: a single shared max-width content wrapper (e.g. a `PageContainer` / consistent `max-w-*` + horizontal padding) so any gutter is uniform and intentional, OR consistent full-bleed with standard padding — implementer picks the one that reads best with the existing pages and applies it everywhere.

- [x] **DOP-014 — Consistency pass.** Introduce/standardize one content-width convention and apply it to the main pages so the right-gutter is consistent (not a per-page accident). Keep it LIGHT — this is a consistency pass, not a redesign: don't change each page's internal layout, just normalize the outer content container. If a page genuinely needs to be full-width (Library color-map, Tools wheel), exempt it intentionally and note why. Acceptance: main pages share one content-width rule; no page has a uniquely odd wasted gutter; nothing overflows. If this balloons beyond a contained change, do the high-value pages and FLAG the rest rather than sprawling.
  - Done. CONVENTION CHOSEN: **full-bleed + uniform `p-6` gutter** (no max-width content cap). Rationale: the audit's "270px wasted gutter" was NOT a divergent max-width — no main page actually caps content; the inconsistency was each page hand-rolling its own outer `flex h-full flex-col gap-6 p-6` div with no single source of truth. The terminal aesthetic (dense panels, the colour map, the tools wheel) wants the full canvas, so full-bleed is the right rule. Codified as a new shared `PageContainer` primitive (`src/components/shell/PageContainer.tsx`): `flex h-full flex-col gap-6 p-6`, full-bleed, scroll delegated to the AppShell `<main>` scroller (an optional `scroll` prop gives a self-contained scroll column where a page owns a sticky footer).
  - ADOPTED on the plain single-column pages: **library, recipes, tools(hub), planner** (drop-in — behaviourally identical to their old wrappers). The two new pages (planner/projects) follow the convention from birth.
  - EXEMPT (kept their bespoke shells, but already on the same `p-6` gutter so the right edge stays uniform): **dashboard** (master-detail inspector pane + sticky UPCOMING-EVENTS ticker), **projects** (same master-detail row layout), **collection** (sticky CollectionStatsBar footer beneath a flex-1 region), **focus** (the bench's own layout). Genuinely full-bleed inner content — the **Library colour-map** and **/tools/wheel** — was never capped and isn't now; PageContainer only standardises the outer gutter, never the inner content width. Nothing overflows; all suites green.
