# Environment variables — the complete manifest

Every `process.env` read in `src/`, what breaks without it, and how it fails.

Generated by auditing the source, not from `DEPLOY.md` — which documented ~7 of
these while the app reads 24. The gap matters because **almost nothing here
crashes when it's missing.** Features degrade quietly: checkout renders a stub,
uploads refuse, email vanishes into a server log, admin pages 404. A from-scratch
redeploy can come up looking healthy and be silently broken in four places.

**Set every var in the Vercel `Production` environment specifically** — not just
Preview/Development.

> **The Redeploy trap.** Env vars are snapshotted at build time. Hitting
> **Redeploy** on an existing deployment reuses the *old* snapshot, so a newly
> added var won't be there. Push a fresh commit to bake it in. This has bitten
> this project more than once — see `email-deliverability-setup`.

## Hard-required — the app is broken without these

| Var | Read by | Without it |
|---|---|---|
| `DATABASE_URL` | `src/db/client.ts` | Falls back to `file:./data/local.db` — **a serverless-local SQLite file**. The app boots and appears to work, then loses every write. The most dangerous failure here, because it looks fine. |
| `DATABASE_AUTH_TOKEN` | `src/db/client.ts` | Turso rejects the connection; every query fails. |
| `AUTH_SECRET` | NextAuth, `extensionToken.ts` | Sessions can't be signed. Nobody can log in. |
| `AUTH_URL` / `NEXT_PUBLIC_APP_URL` | password reset, recovery + signup verification | Falls back to `http://localhost:3000`, so **every emailed link points at localhost** and is useless to the recipient. |

## Required for a feature to exist at all

| Var | Feature | Failure mode when unset |
|---|---|---|
| `STRIPE_SECRET_KEY` | Checkout | `isStripeConfigured()` false → `/pricing` renders the "wire-up pending" stub instead of real buttons. **No error, no revenue.** |
| `STRIPE_PRICE_PRO_MONTHLY` | The $3.99/mo tier | Same as above — this is the only tier actually sold. |
| `STRIPE_WEBHOOK_SECRET` | Granting access after payment | Webhook returns 400. **Customers pay and are never upgraded.** Worst failure in the list. |
| `AUTH_RESEND_KEY` | All outbound email | No key ⇒ the mail is `console.log`ed to the server and **never sent**. Signup verification, password reset and recovery all silently die. |
| `AUTH_EMAIL_FROM` | Sender identity | Defaults to `Mini Mainframe <no-reply@localhost>` — rejected or spam-filed. |
| `BLOB_READ_WRITE_TOKEN` | Model photos, share cards | `isBlobConfigured()` false → uploads return a clean handled error. Degrades honestly, at least. |
| `MM_ADMIN_EMAILS` | `/admin/comp`, `/admin/gallery`, `/admin/users` | **Fails closed: nobody is an admin.** All three 404 — indistinguishable from an unverified email. Comma-separated; the account's email must also be verified. |
| `ANTHROPIC_API_KEY` | AI recipes, paint scan, gallery moderation | AI features error; gallery moderation fails open to human review. |

## Optional — cosmetic or secondary

| Var | Effect when unset |
|---|---|
| `SUPPORT_EMAIL` + `NEXT_PUBLIC_SUPPORT_EMAIL` | Renders `CHANGE_ME@mini-mainframe.com` to real users. **Set both** — the bare one is stripped from client bundles. *(Currently set correctly in prod.)* |
| `SUPPORT_URL` + `NEXT_PUBLIC_SUPPORT_URL` | Support link falls back to the mailto. |
| `NOTION_TOKEN`, `NOTION_FEEDBACK_DATABASE_ID` | In-app feedback isn't recorded to Notion. |
| `STRIPE_PRICE_PRO_LIFETIME`, `STRIPE_PRICE_FOUNDER` | **Dormant tiers.** Code reads them; nothing sells them. Safe to leave unset. |
| `MM_AI_DAILY_LIMIT`, `MM_GALLERY_DAILY_LIMIT`, `MM_SIGNUP_DAILY_LIMIT`, `MM_SCAN_DAILY_LIMIT` | Sensible defaults (50 / 20 / 10 / 20 per day). |
| `MM_RESET_WINDOW_LIMIT`, `MM_MAIL_WINDOW_LIMIT` | Defaults 3 forgot-password requests per username and 5 outbound emails per recipient, each **per 15 minutes** (R2-19). Short windows on purpose — the subject is attacker-chosen, so a long one would let an attacker hold a real user off their own reset. |

## Must NOT be set in production

| Var | Why |
|---|---|
| `ALLOW_TEST_AUTH` | Enables `/api/test/sign-in`, which mints a session for **any email with no password** and grants comp access. Unset ⇒ the route 404s. **Setting this in production is a full authentication bypass.** |

## Verifying a deploy

Cheap checks that catch the silent failures:

```bash
# Stripe wired? A configured webhook rejects an unsigned POST with
# 400 "Missing signature". 503 means STRIPE_WEBHOOK_SECRET is missing.
# NOTE the path is /api/billing/webhook — /api/stripe/webhook does not
# exist and 307s through the proxy, which reads like a pass but isn't.
curl -s -X POST https://www.mini-mainframe.com/api/billing/webhook

# Support placeholder leaking to users?
curl -s https://www.mini-mainframe.com/sign-up | grep -c "CHANGE_ME@"   # want 0

# Test-auth bypass exposed? MUST be 404.
curl -s -o /dev/null -w "%{http_code}\n" -X POST https://www.mini-mainframe.com/api/test/sign-in

# Admin allowlist reaching the build? Signed in as an admin, /admin/users
# should load rather than 404.
```

`BILLING_ENFORCED` is a **code constant** (`src/lib/billing/plans.ts`), not an
env var — currently `true`. Flipping it to `false` opens every paid feature to
everyone, so it is deliberately not env-configurable.
